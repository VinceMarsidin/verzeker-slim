## Overzicht

VerzekerSlim heeft een eenvoudig rollensysteem met twee rollen: **`user`** (standaard, voor elke bezoeker die een account aanmaakt) en **`admin`** (toegang tot het [beheerdersdashboard](/admin/dashboard)).

## Hoe accounts werken

- Iedereen kan via **Registreren** een account aanmaken met naam, e-mailadres en wachtwoord.
- Authenticatie loopt via **better-auth**, met sessies die via een cookie worden bijgehouden.
- Elk nieuw account krijgt automatisch `role: 'user'`.

## Wat kan een gewone gebruiker (`user`)?

- Inloggen/uitloggen en het eigen account beheren op `/account` (naam, profielfoto, wachtwoord, e-mailadres, account verwijderen).
- [Reviews plaatsen](/maatschappijen) op maatschappij-detailpagina's.
- De eigen geplaatste reviews terugzien op `/account`.
- Het [contactformulier](/admin/contact) gebruiken (dit kan ook zonder account).

## Wat kan een beheerder (`admin`) extra?

Toegang tot `/dashboard`, met vier tabbladen:

- **Premies** toevoegen, bewerken en verwijderen
- **Maatschappijen** toevoegen, bewerken en verwijderen (inclusief logo/homepage-afbeelding uploaden)
- **Reviews** bekijken, filteren en modereren (verwijderen)
- **Contactberichten** bekijken

Zie [Dashboard overzicht](/admin/dashboard) voor de details per tabblad.

## Iemand admin maken

Er is geen zelfbedieningsscherm in de applicatie zelf om een gebruiker admin te maken — dit gebeurt via een command-line script, niet via de UI.

**Nieuw account meteen als admin aanmaken:**

```
pnpm create-admin "Naam" email@voorbeeld.com wachtwoord123
```

**Bestaand account admin maken:**

```
pnpm promote-admin email@voorbeeld.com
```

Dit script deblokkeert het account ook automatisch als het geblokkeerd was.

**Problemen met inloggen diagnosticeren** (bijvoorbeeld als iemand meldt dat inloggen niet lukt):

```
pnpm diagnose-user email@voorbeeld.com
```

Toont de rol, of het account bestaat, en of het geblokkeerd is.

:::note
Deze scripts moeten gedraaid worden in de omgeving waar je database daadwerkelijk bereikbaar is — lokaal (met een correct ingestelde `DATABASE_URL` in `.env.local`) of in de shell/console van je hostingplatform (bijv. Railway) tegen de productiedatabase.
:::

Na het inloggen (of herladen van de sessie) heeft het account toegang tot het dashboard.
